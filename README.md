# B ABLE

タスク管理をゲーミフィケーションし、「早く終わらせること」自体に報酬を与えるアプリの MVP。

## コンセプト

一般的なタスク管理アプリは、締切間際に慌てて処理しても、余裕をもって処理しても、
アプリ上の結果は同じ「完了」である。B ABLE は完了の**質**を報酬に変換する。

タスクを完了すると建材（ミノ）が手に入り、それを積んでバベルの塔を建てる。
このとき手に入るミノの形は、完了時点で期限までどれだけ残っていたかで決まる。

| 残日数 | マス数 | 形 |
| --- | --- | --- |
| 3日以上前 | 4 | 素直に置ける |
| 2日前 | 5 | やや扱いにくい |
| 1日前 | 6 | 隙間ができる |
| 当日 | 7 | かなり不利 |
| 超過 | 8 | ほぼ処理不能 |

マス数が増えれば得られるブロック総量は増えるが、形状はランダム成長で生成されるため
大きいほど歪になり、ライン消去（＝階層の完成）が難しくなる。
「量は増えるが割に合わない」という損得構造で、先延ばしに一貫したペナルティを与える。

塔の階数に応じて背景が変化する: 1〜9F 地上 / 10〜49F 中空 / 50〜99F 上空 /
100〜299F 大気圏 / 300F〜 宇宙。

## 画面

- **カレンダー**: 月表示。期限の入ったタスクを、緊急度の色ドットで表示する。
- **リスト**: 掲示板に貼られた依頼書。重要度（星）と、いま完了した場合に得られるミノを並べて表示する。
- **babel**: 手持ちのミノを落として積む。ラインが揃うと1階ぶん建設される。

落下速度は意図的に遅くしてある。落下中に他の画面へ移動しても盤面は保持されるため、
「落下中に予定を確認して戻る」操作が成立する。速度で急かす設計にはしていない。

## 技術構成

- React 18 + TypeScript + Vite
- シミュレーション層 (`src/core`) と描画層 (`src/app`) を完全分離。
  `core` は DOM / React に依存せず、Node から直接実行してテストできる
- 固定タイムステップのゲームループ + `useSyncExternalStore` で React に接続
- 状態は localStorage に永続化（バックエンド・外部 API なし）
- ポリオミノはタスク ID をシードにした決定的乱数で生成するため、
  リスト上のプレビューと実際に手に入るミノが一致する

設計の詳細と選定理由は [ARCHITECTURE.md](./ARCHITECTURE.md)、
Claude Code で作業する際の規約は [CLAUDE.md](./CLAUDE.md) を参照。

## 開発

```bash
npm install
npm run dev
```

## Vercel へのデプロイ

```bash
npm i -g vercel
vercel        # プレビュー
vercel --prod # 本番
```

GitHub に push して Vercel から import しても、Vite は自動検出されるため設定は不要。

## 操作

- 画面下のボタン、またはキーボード（← → 移動 / ↑ 回転 / ↓ 落下 / Space 設置）
